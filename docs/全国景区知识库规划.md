# 全国景区与 RAG 接入规划

第一份真实样例为承德避暑山庄。网页仍是一个「旅游景区」入口、一个景区讲解员，当前只有避暑山庄可用。全国景区选择与 RAG 尚未实现，本次完成独立景区编号、短版会话资料、带出处的知识条目和有效期字段。

## 新增景区资料

每个景区使用独立目录与稳定编号，catalog 记录名称、别名、省市。只收录可核实资料，优先景区官网、管理机构、文物部门和世界遗产等原始来源。新增名称相同或相近的景点时必须保留所在景区编号，避免将承德金山岛与镇江金山寺混淆。

景点历史与特色按主题分条；路线建议与史实分开；票价、开放时间、活动公告单独存放，记录发布日、核对日与有效期。记录的有效期结束后不再用于当前服务答复，不能仅凭“最近抓取”延长公告效力。来源互相矛盾时保留审核问题，先排除冲突内容，而不是让模型任选。

`profile.json` 是审核后的短版资料，不由整篇网页自动拼接。用户在设置里修改景区时，需要完整替换相应介绍、景点、路线与服务信息，避免只改名称留下其他景区事实。

## 后续问答检索

预期流程：确定当前景区 → 获得游客问题 → 按 `scenicId` 和有效期过滤 → 检索相关知识条目 → 将少量相关内容与出处提供给回答模型 → 使用既有复刻音色播放。景区选择变化要结束旧会话，清除旧景区检索缓存，重新建立会话。

先验证既有实时语音服务的逐轮知识注入或工具调用能力，再确定接入方式；不把“把全部资料放进会话提示词”当作已经完成 RAG。长资料可以使用关键词与向量检索结合，并保留文档 ID、来源与版本。用户无需听模型朗读 URL，出处可记录在后台或资料管理界面，继续维持纯语音对话。

没有匹配资料时明确说明目前没有核实该内容，引导官方或人工确认。系统不猜票价、现场关闭、实时位置，也不允许把网页或资料中的指令当作系统指令执行。核对日期不等于实时查询日期。

## 接入验收

- 同一问题在不同景区只检索该景区内容，遇到同名景点不会串库。
- 过期公告不进入当前门票或开放时间回答，缺失信息不会生成具体数字。
- 回答可回溯到知识条目与官方来源，路线建议明确为建议。
- 实测语音响应延迟、插话打断和检索超时处理，保留用户音色与纯语音页面。
- 更换景区、更新资料后重新开始对话，不沿用旧景区缓存。

未来公开景区部署另行处理内容更新责任、服务额度和既有人脸模型的商业许可；本次仍为 Windows 本机测试。
