# 实时口型和表情

目标是与数字人即时交谈：每次新回答由豆包实时生成用户的复刻声音，再由 Simli 实时驱动照片中的人物。网页接收 WebRTC 声画流，不生成、保存或循环播放预录视频，不显示对话文字或字幕。

## 当前状态

2026-10-09，用户提供的 Simli 凭据已通过官方 `/faces` 接口认证，HTTP 200，账号暂时没有人像模型。密钥已使用 Windows CurrentUser DPAPI 保存在 `.private/simli/settings.json`，不返回浏览器，不写 localStorage，不以明文写文件。原办公室照片文件保持不变。

同日用户确认，控制台创建本人实时头像要求付费。因此当前阻碍包含头像创建费用，并非只缺 Face ID；不能把平台的试用分钟数理解为免费创建本人头像。用户选择免费试用，本应用尚未购买服务、创建收费头像或切换视频供应商。

免费替代候选：截至 2026-10-09，[Anam 官方价格页](https://anam.ai/pricing) 明确列出 Free 档包含 Image Upload Avatars、一个自定义头像、API 接入、每月 30 分钟及每次会话最多 3 分钟。[官方外部语音集成说明](https://anam.ai/blog/cartesia) 支持将第三方生成的实时音频送入 audio passthrough，以音频驱动口型，因此技术上可继续使用现有豆包复刻音色，无需改用内置声音。具体账户权限、本人照片效果和本机网络延迟尚未验证，Anam 接入代码尚未实施。头像额度与豆包语音用量分别计算，不能据此宣称整个系统永久免费。

本机接入已准备：浏览器使用一个 `video` 元素播放同一 WebRTC 流中的声音和画面；不另行播放豆包声音，防止声音提前或播放两次。豆包输出 24 kHz PCM，带抗混叠过滤的有状态转换输出 16 kHz PCM，保持音高、语速及分块时序。

插话或点击停止时立即暂停并静音声画，发送 `SKIP`，关闭旧 WebRTC 接收流，隐藏旧画面。为防止网络停顿时误把迟到尾音当作新回答，每个后续问题开始时都会保守隔离曾发送过音频的旧流。后台在用户提出下一问期间重新连接人像，将新回答按原顺序暂存到新流就绪后发送。这样不会把旧 RTP 缓冲重新当作新回答播放，也不依赖协议未保证的 SKIP 确认事件。重连会增加网络和会话开销；真实模型就绪后需要实测速度及平台并发限制。

正常回答的 `SILENT` 信令不直接静音网页，因为控制信令可能早于接收端尾音播放。根据实际音频输出、输入总时长和接收端播放时钟判断结束。结束事件不追加人为的静音片段。

人像模型未就绪时，主页面继续现有的照片语音模式。不能据本机测试宣称用户照片的云端写实口型、面部自然度或声画延迟已经验证。

## 准备一次可实时驱动的人像

1. 打开 [Simli 创建头像](https://app.simli.com/create/select)，使用当前办公室照片。也可在本机「分身设置 → 实时口型与表情」下载原图。
2. 查看控制台的试用余额、头像准备费用及生成状态。这里只准备一个可驱动的人像模型，不是制作固定的视频。若要求另外付费，先停在该页面；本应用不会购买套餐或自动充值。
3. 人像准备完成后，在 **Your Avatars** 复制 **Face ID**。模型准备所需时间以平台状态为准。
4. 打开 [本机网页](http://127.0.0.1:4173/)，进入「分身设置 → 实时口型与表情」。已保存的 API Key 留空即可沿用；填 Face ID，确认对应当前照片，勾选启用，保存。
5. 关闭设置，开始对话。只有收到真实画面并接通麦克风后，界面才显示「声画对话已连接」。尚未接通时显示连接状态或错误。

永久密钥只在本机后端读取。浏览器得到短期 session token 与临时 ICE 参数，不持久存储。麦克风输入继续发送火山引擎，生成的回答音频发送 Simli。每次视频会话最长 15 分钟，最长空闲 5 分钟；实际额度用量遵循平台规则。

## 验证与边界

`tests/simli.test.mjs` 验证 DPAPI 保密、固定 Face ID、缺失人像不创建会话、错误信息隐藏密钥、跨来源拒绝。`tests/pcm-resampler.test.mjs` 验证时长、音高、分块一致性及高频抗混叠。`tests/browser/simli.spec.mjs` 通过原生 Chrome WebRTC 在本机产生测试声画，验证同流播放、16 kHz 输入、停止及新流隔离、取消连接和麦克风释放。这些测试不调用 Simli 视频生成引擎，不证明照片人物的自然表情或真实口型。

视频模式的云端对话截断位置使用输出播放时钟作保守估计，不把已上传但尚未播放的音频当作已听完。WebRTC 抖动及检测间隔可能使位置存在误差，真实模型连接后还需校准。视频增加处理和网络延迟，先前纯语音约 0.78 秒的受控测试结果不能作为视频模式的速度保证。
